# Firefighter

A small 3D city game: a rookie firefighter's "test task". Drive the fire truck through traffic, take the hose off
its reel and put out the fires the dispatcher calls in, one at a time, while the damage bill for everything you
knock over keeps growing. Unity **6000.3.29f1**, URP (3D renderer), New Input System, Zenject.

Open this folder in Unity Hub. Play mode starts at `BootstrapScene` (Build Settings index 0), which loads
`MainScene`. Toolbar Shortcuts has Bootstrap Play plus buttons for both scenes.

## Layout

| Path | What lives here |
|------|-----------------|
| `Assets/_Project/Scripts/Runtime/Core/` | `Firefighter.Core`: the simulation. City layout and props, vehicles, traffic, pedestrians, fire and the hose, the damage bill, lighting, `IPlayerState` |
| `Assets/_Project/Scripts/Runtime/Gameplay/` | `Firefighter.Gameplay`: the player, mission, comedy layer, hydrant geysers, HUD, minimap, soundscape and the composition root (`Bootstrap/`) |
| `Assets/_Project/Scripts/Editor/` | `Firefighter.Editor`: scene builders under **Tools/City/** |
| `Assets/_Project/Scripts/Dev/` | `Firefighter.Dev` (Editor only): trailer recording tools |
| `Assets/_Project/Scripts/_Generated/` | `Firefighter.Generated`: constants from the toolkit source generators |
| `Assets/_Project/Tests/EditMode/` | `Firefighter.Tests.EditMode`: tests of the pure logic |
| `Assets/_Project/Configurations/` | ScriptableObject data: city layout, traffic, mission and comedy lines, damage prices |
| `Assets/_MyToolkit/` | Shared tools. Do not put game-specific code here. |
| `Assets/Plugins/` | Zenject, UniTask, DOTween, Odin Inspector |
| `Assets/ThirdParty/` | Art and FX packs (SimpleTown, EpicToonFX, Hovl, ParticleTrails, StickmanFantasyPack) |

### Dependency rules

- `Core` knows nothing about `Gameplay`; the asmdefs make the compiler enforce it. What the simulation needs to know
  about the player goes through `IPlayerState` (Core), which `PlayerModeController` (Gameplay) implements.
- `CityInstaller` (Gameplay/Bootstrap) is the only class that knows every module. Scene systems, the player and
  HUD views are bound there and reach each other through `[Inject]`; `[SerializeField]` is for a component's own
  children, assets and tuning.
- Text and tuning that a designer may change live in ScriptableObjects (`MissionScript`, `ComedyScript`,
  `DamagePrices`, `CityLayout`, `TrafficSettings`), not in code.
- The HUD is uGUI with the built-in font (it carries Cyrillic) on canvases that scale from 1920×1080.

## Building the scene

`MainScene` is generated by the builders in **Tools/City/**. `Setup Main Scene (full rebuild)` rebuilds everything;
the other items rebuild one part (fires, HUD, mission, sound...). Builders keep edited assets (mission and comedy
lines, prices) and replace only what they created.

Some third-party prefabs (EpicToonFX effects, Hovl "Toon punch", the star trail) are not referenced at runtime: the
builders copy them into `Assets/_Project/Prefabs/Fx`. Keep them while you re-run the builders.

## Tests

Window > General > Test Runner > EditMode: `Firefighter.Tests.EditMode` (game) and `MyToolkit.Tests.EditMode`
(toolkit).

## `_MyToolkit` modules

All namespaces are `MyToolkit.<Module>` (Editor code: `MyToolkit.<Module>.Editor`). Runtime: AssetLoader, Audio,
Save, SceneLoader, StateMachine, UI, Registry, ParticleFx, DamagePopup, Steam (not wired), ApplicationLifecycle,
Global (`Result`, logger, `AsyncGetter`). The toolkit must not reference game code: the game implements
`ISceneCatalog` (`Gameplay/Bootstrap/SceneCatalog.cs`) and binds it before `SceneLoaderServiceInstaller.Install`.
